# 0006: FFI

Status: proposed, 2026-08-10 (not implemented)

## Context

Scripts sometimes need native libraries the runtime does not wrap:
sqlite, zstd, vendor SDKs. The npm escape hatches do not exist here:
native node addons (.node, N-API) have no loader in choq, and wasm
builds (sql.js) have no engine, quickjs-ng ships no WebAssembly.

Deno and bun answer this with a dlopen-style FFI where the script
declares symbol signatures and the runtime builds the calls at
runtime.

## Options

### libffi FFI (deno/bun model)

`libloading` for dlopen plus the `libffi` crate for call construction.
Measured binary cost with both linked and exercised: +65KB. Sketch:

```clojure
(require '[choq.ffi :refer [dlopen]])

(def libm (dlopen "libm.dylib"
                  {:cos {:args [:f64] :ret :f64}}))

((:cos libm) 1.0)
```

Effort tiers:

- v1 (a focused day): scalars, i64/u64 as BigInt, strings in, blobs
  via TypedArray. QuickJS ArrayBuffer data pointers are stable, so
  buffers pass as pointers without copies. Covers flat C APIs.
- The long tail: callbacks (libffi closures; the engine is single
  threaded, so native code calling back from another thread is
  off the table in v1), structs by value (layout descriptors),
  ownership of returned pointers.

Sandbox interaction, per ADR 0005: dlopen is arbitrary native code
with full process privileges and engine limits do not survive a
native call. FFI is excluded from `--sandbox` entirely; deno labels
its equivalent unsafe for the same reason.

### Built-in modules instead of FFI (preferred per capability)

For known needs, compile a Rust crate in and expose it under the node
API name, like zlib and net today. For sqlite: rusqlite (bundled,
about +1MB) exposed as `node:sqlite` (the node 22 `DatabaseSync`
API). Same behavior on all platforms including windows, no system
library variance, npm libraries targeting `node:sqlite` work, and the
open path stays governable by sandbox flags.

### Wasm runtime

Would preserve the sandbox for native-speed code, but embedding
wasmtime is a much larger dependency than libffi and is a separate
project, not an FFI substitute.

## Decision (proposed)

Both, in order: built-in modules for named needs (sqlite first), FFI
as the escape hatch for the long tail. FFI v1 is scalars, strings and
buffers, no callbacks and no structs, and is unavailable under
`--sandbox`.
